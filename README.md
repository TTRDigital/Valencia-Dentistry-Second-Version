# Valencia Dentistry website

Second version of the Valencia Dentistry website (Dr. Nuriel Lavi, DDS), a dental practice on Tourney Road in Valencia / Santa Clarita, CA. Built by TTR Digital Marketing on Next.js 16 (App Router, Cache Components), TypeScript, Tailwind CSS 4 and Sanity (Studio embedded at `/cms`), deployed on Vercel.

- **Brand, facts and URLs** come from the practice's first site (valencia-dentistry.vercel.app / valenciadentistryca.com): name, Dr. Nuriel Lavi, contact details, logo and case photos. The page content and all 57 URLs carry over from the earlier site the first version was built from; every one answers 200. See `docs/content-inventory.md`.
- **Images come from the first site.** Every photo, the before/after cases, the insurance logos and the logo are taken from valencia-dentistry.vercel.app (`public/images/office`, `cases`, `insurance`, `brand`; descriptions in `content/office-images.ts`). The ten photos in which another dentist (coat embroidered "Dr. Jason Verdi") can be identified are not used; see `docs/open-items.md`. Nothing from the earlier practice's site remains.
- **Design** is an original "boutique spa meets modern clinic" system: warm charcoal/ivory/taupe tokens taken from the logo, Fraunces + Manrope, hairline borders, slow reveals. See `docs/design-direction.md` and `/styleguide` (noindex).
- **Copy** was rewritten in a warmer, premium voice under the rules in `docs/copy-guide.md`; medical claims were softened and everything uncertain is listed in `docs/open-items.md`.

## How it works

| Part | Where |
|---|---|
| Practice facts (address, hours, phone, booking link, reviews, cases, technology, insurers) | `content/site.ts` |
| Service page content (18 files) | `content/services/*.ts` (typed by `content/types.ts`) |
| Blog articles | `content/posts.json`, generated by `npm run build-content` from the crawl + `content/posts-meta/*.json` |
| Legal pages | `content/legal.json` |
| Marketing page copy (about, offer, emergency, home FAQs) | `content/pages.ts` |
| Image sizes and blur placeholders | `content/images.json` (`npm run images`) |
| CMS loader with built-in fallback | `src/lib/cms.ts` (cached for an hour, tag `content`, refreshed by the publish webhook) |
| Sanity schemas / Studio | `sanity/schemaTypes/*`, `sanity.config.ts`, `src/app/cms` |
| Seed | `content/seed.json` (`npm run build-seed`) → `npm run seed` |
| Header (transparent over heroes, solid on scroll), mega menu, mobile menu, sticky bottom bar | `src/components/layout/*`; route groups `(hero)` and `(solid)` choose the header variant |
| SEO metadata, JSON-LD (Dentist, Person, WebSite, MedicalProcedure, Article, BreadcrumbList, FAQPage) | `src/lib/seo.ts`, `src/lib/schema.tsx` |
| Forms and lead delivery | `src/components/forms/AppointmentForm.tsx`, `src/app/api/lead/route.ts`, `src/lib/lead.ts` |
| Redirects (301, no chains) | `redirects.ts`; unknown URLs → `src/proxy.ts` rewrites to the 404 page |
| Analytics | `src/components/layout/Analytics.tsx` (GTM after idle/first interaction, Consent Mode defaults) |

## Setup

```bash
npm install
cp .env.example .env.local   # fill in GHL_WEBHOOK_URL etc.
npm run dev                  # http://localhost:3000 and http://localhost:3000/cms
```

### Sanity

1. Set the practice's project ID in `sanity/env.ts` (pinned on purpose; `NEXT_PUBLIC_SANITY_PROJECT_ID` is ignored because this environment uses it for another site).
2. In sanity.io/manage > API > CORS origins, allow `http://localhost:3000`, the Vercel preview URL and `https://valenciadentistryca.com` + `https://www.valenciadentistryca.com` (with credentials).
3. Load the content: `SANITY_WRITE_TOKEN=<editor token> npm run seed` (adds missing documents) or `npm run seed -- --force` (overwrites). 86 documents: site settings, navigation, doctor, 2 testimonials, 7 before/after cases, 14 FAQs, 18 services, 30 posts, 2 legal pages, 10 pages. Images are referenced by their path in `public/images`; editors can upload replacements.
4. Publish webhook: API > Webhooks, URL `https://valenciadentistryca.com/api/revalidate/?secret=<SANITY_REVALIDATE_SECRET>`, trigger on create/update/delete. Pages refresh within seconds; otherwise within an hour.
5. Until the project is connected, the site renders the built-in content and `/cms` shows a notice.

### Forms

Native forms on Contact, Appointment, New Patient Offer and Emergency pages: inline validation, honeypot, 3-second time trap, optional Cloudflare Turnstile (`NEXT_PUBLIC_TURNSTILE_SITE_KEY` + `TURNSTILE_SECRET_KEY`). The API posts JSON to `GHL_WEBHOOK_URL`:

`source, form, tags, submitted_at, first_name, last_name, name, email, phone (E.164), phone_raw, service, preferred_time, comments, page_url, utm_source/medium/campaign/term/content, gclid, fbclid, fields{label: value}`

On success the visitor goes to `/thank-you/`; on failure the lead is logged server-side and the visitor is shown the phone number. Test locally with a webhook catcher (`GHL_WEBHOOK_URL=http://127.0.0.1:4545/`); do not point the preview at the live webhook unless you want test leads in GoHighLevel.

### Vercel

Build command `next build`. Add the variables from `.env.example` (not `SANITY_WRITE_TOKEN`). Set `NEXT_PUBLIC_SITE_URL` to the final domain. Point the domain's DNS at Vercel; the old `/sitemap_index.xml` 301s to `/sitemap.xml`.

## Quality checks

```bash
npm run typecheck
npm run lint
npm run build
npm run audit -- http://localhost:3000      # launch checks (see scripts/audit.ts)
npm run shots -- http://localhost:3000 out   # screenshots at 390/768/1024/1440/1920 + overflow/tap-target check
```

Lighthouse (mobile), the launch audit and the screenshot QA were run against a production build; results, caveats and sample screenshots are in `docs/qa-report.md` and `docs/screenshots/`.

## Editing content without the CMS

Everything the CMS holds also lives in `content/`. Edit the TypeScript/JSON there, run `npm run build-seed` to regenerate the seed, and commit. `npm run build-content <crawl-dir>` regenerates the blog and legal JSON from the original crawl (not in the repo).

## Accessibility

WCAG 2.2 AA targets: skip link, visible focus, one H1 per page, labelled forms with inline errors, native accordions, keyboard-operable carousels and before/after sliders (range inputs), focus-trapped popup, reduced-motion and data-saver respected (no video, no reveal animation), 44px tap targets, AA contrast on every token pair.
